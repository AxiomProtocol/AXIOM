================================================================================
                              ABSTRACT
================================================================================

The Axiom Protocol is a governance-first wealth infrastructure designed to
bridge digital capital formation and physical asset acquisition for underserved
communities. Operating on Arbitrum One with 72+ verified automated control
layers, the protocol provides institutional-grade disclosure, deterministic
risk management, and community-governed capital deployment across a vertically
integrated financial stack.

Core capabilities include:

  - A dual-ecosystem stablecoin (AXUSD) designed to align with the GENIUS Act
    framework
  - A three-layer treasury policy with automated stress response
  - An Adaptive Metrics Engine for regime-aware capital management
  - A physical asset pipeline connecting community savings to land acquisition,
    housing ownership, and food distribution networks

The protocol operates through a 52-week operational playbook at $100/week,
validating each component through live deployment before scaling. All capital
decisions pass through Axiom Sentinel, a unified risk authorization layer with
cryptographically auditable decision trails. Market intelligence from MIRDT
provides probabilistic trend-following analysis with paper-only execution and
SHA-256 audit hashing.

This document serves as both whitepaper and executive summary, providing
allocators, participants, and regulators with a complete view of the protocol
architecture, risk framework, and operational status.

================================================================================
                 SECTION V: ADAPTIVE METRICS ENGINE (AME)
================================================================================

The AME is a deterministic financial computation engine that provides
regime-aware risk management through pure-function math. All computations
are reproducible, auditable, and free of stochastic elements.

  Model Version:       AME-v1.0.0
  Maturity:            Live

CORE COMPUTATION PIPELINE
-------------------------

  Step 1: RATIO COMPUTATION
    Inputs: treasuryCapitalUsd, liquidReservesUsd, outstandingLiabilitiesUsd,
            redemptionCapacityUsd
    Outputs: Coverage Ratio (CR), Reserve Ratio (RR), Loss Buffer Ratio (LBR),
             Liquidity Depth (LD)

    CR = treasuryCapital / outstandingLiabilities
    RR = liquidReserves / outstandingLiabilities
    LBR = (treasuryCapital - liquidReserves) / outstandingLiabilities
    LD = redemptionCapacity / outstandingLiabilities

  Step 2: STRESS NORMALIZATION
    volShock         = clamp(realizedVolatility / rvRef, 0, 1)
    drawdownPressure = clamp(drawdownPct / ddRef, 0, 1)
    flowStress       = clamp(flowImbalance, 0, 1)
    liquidityStress  = clamp(liquidityCompression, 0, 1)

  Step 3: REGIME SCORE (RS)
    RS = wv * volShock + wd * drawdownPressure + wf * flowStress
         + wl * liquidityStress

    Weights: wv=0.30, wd=0.25, wf=0.25, wl=0.20
    Output range: [0, 1]

  Step 4: POLICY MULTIPLIER (PM)
    PM = 1 / max(1 - RS, 0.05)
    Clamped to [1.0, 10.0]

  Step 5: ADAPTIVE TARGETS
    crTarget  = baseCR * PM    (base: 1.50)
    rrTarget  = baseRR * PM    (base: 0.10)
    lbrTarget = baseLBR * PM   (base: 0.03)
    ldTarget  = baseLD * PM    (base: 0.15)

  Step 6: REGIME BAND DETERMINATION
    RS < 0.25   -->  STABLE
    RS < 0.50   -->  CAUTION
    RS < 0.75   -->  STRESS
    RS >= 0.75  -->  CRISIS

  Step 7: PAYOUT FACTOR
    PF = basePayout * (1 - RS^2)
    PF = 0 in CRISIS regime
    Clamped to [0, 1]

  Step 8: POLICY ACTIONS (sorted by priority)
    0. ACTION_CRISIS_LOCKDOWN           RS >= 0.80
    1. ACTION_FREEZE_DISTRIBUTIONS      CR < crTarget
    2. ACTION_LIQUIDITY_DEFENSE_MODE    LD < ldTarget
    3. ACTION_REDIRECT_FLOWS_TO_RESERVES RR < rrTarget

BASE CONFIGURATION
------------------
  Parameter          Value      Description
  ---------          -----      -----------
  rvRef              0.80       Realized volatility reference
  ddRef              0.35       Drawdown reference
  Base CR Target     1.50       Coverage ratio base target
  Base RR Target     0.10       Reserve ratio base target
  Base LBR Target    0.03       Loss buffer ratio base target
  Base LD Target     0.15       Liquidity depth base target
  PM Range           [1.0,10.0] Policy multiplier bounds
  RS Epsilon         0.05       Minimum denominator for PM

STRESS TESTING SCENARIOS
------------------------
  MARKET_CORRECTION:    15% treasury drawdown, RV override 0.60
  LIQUIDITY_CRISIS:     50% redemption capacity drawdown, FI override 0.80
  BLACK_SWAN:           50% treasury + 70% RC drawdown, RV 0.95, DD 0.60
  DEPEG:                15% liability increase, FI override 0.70
  GOVERNANCE_ATTACK:    25% treasury + 30% liability + 40% RC drawdown

       SECTION VII: MARKET INTELLIGENCE & RISK DISCLOSURE (MIRDT)
================================================================================

MIRDT provides probabilistic trend-following analysis with full audit trails.
The execution model is deterministic and operates in paper-only mode with
human confirmation gates at every stage. No live capital is deployed through
MIRDT.

  Maturity:            Live
  Execution Mode:      Paper trading only
  Audit:               SHA-256 hash chain

EXECUTION PIPELINE
------------------
  1. Price Fetching:     Real-time OHLCV from Alpha Vantage (US equities)
                         and CoinGecko (digital assets)
  2. Direction Inference: Trend detection via moving average alignment
  3. Regime Classification: Market regime state determination
  4. Grade Computation:  Multi-factor signal scoring
  5. Eligibility Checks: Risk constraints and exposure limits
  6. Sizing:             Position sizing based on regime and risk parameters
  7. Entry Classification: Signal categorization for execution readiness
  8. Decision Storage:   Full trace with SHA-256 hash chain

REGIME STATES
-------------
  TREND_UP:
    Sustained upward momentum. Moving averages aligned bullishly.
    Standard allocation permitted.

  TREND_DOWN:
    Sustained downward momentum. Moving averages aligned bearishly.
    Reduced allocation applied.

  RANGE_LOW_VOL:
    Range-bound with low volatility. No clear directional bias.
    Standard allocation applied.

  HIGH_VOL_DISLOCATION:
    Elevated volatility with dislocated price action.
    All non-parameter capital deployment suspended.

SCORE BANDS
-----------
  EXCEPTIONAL:     score >= 0.70
  STRONG:          score >= 0.50
  MODERATE:        score >= 0.31
  WEAK:            score < 0.31

================================================================================
                     SECTION XIV: CUSTODY MODEL
================================================================================

Axiom employs a hybrid custody model with three distinct tiers. Each product
clearly discloses its custody type and associated risk profile.

TIER 1: SELF-CUSTODY (Risk: Low)
---------------------------------
Tokens remain in the participant's personal wallet at all times. The protocol
cannot move, freeze, or access funds under any circumstances. Standard ERC-20
token transfers require participant signature.

  User Control:        Full. Participant signs all transactions.
  Protocol Access:     None. Protocol cannot access participant wallet.
  Withdrawal:          Instant. Transfer tokens anytime.
  Examples:            AXM holding, AXUSD in wallet

TIER 2: AUTOMATED CONTROL LAYER CUSTODY (Risk: Medium)
------------------------------------------------------
Funds held by audited automated control layers on Arbitrum One with defined
rules for deposits, withdrawals, and distributions. Participant must sign a
transaction to deposit. Protocol admin can pause but cannot withdraw
participant funds.

  User Control:        Participant initiates deposits and withdrawals
                       by signing transactions.
  Protocol Access:     Limited to contract rules. Admins can pause but
                       not withdraw participant funds.
  Withdrawal:          Subject to contract rules (may include lock-ups,
                       queues, or conditions).
  Examples:            Participation lockup, Vault Engine positions,
                       Personal Vault

TIER 3: POOLED CUSTODY (Risk: Higher)
--------------------------------------
Funds combined with other participants in a shared pool. Distributions
controlled by fund managers (human or algorithmic) or by rotating group
rules. Share is proportional rather than segregated. Higher counterparty
exposure.

  User Control:        Limited. Participant deposits voluntarily but
                       distributions follow pool rules.
  Protocol Access:     Fund managers control pool operations within
                       defined parameters.
  Withdrawal:          May require approval, queue processing, or
                       adherence to rotation schedules.
  Examples:            Wealth Practice groups, Lending Fund vaults,
                       Capital Pools
