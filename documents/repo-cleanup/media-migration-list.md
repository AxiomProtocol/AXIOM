# Media migration list — files removed from git history during the 5 GB cleanup

This document records every binary media file that was purged from git history during the repo-size cleanup, where it was referenced in the codebase, and where it should live going forward (Google Cloud Storage or Storacha — both are already configured per `replit.md`'s External Dependencies section).

The history rewrite removed these files from every commit. They are NOT lost — they remain available in the working tree as untracked files (they're in the "before" snapshot at `.local/repo-cleanup-backup/` if needed) and can be re-uploaded to object storage from there.

## How to re-upload the legitimate media

For each row in the first table:

1. Locate the working-tree copy (the file is still on disk in the workspace; it just stopped being tracked by git after the rewrite).
2. Upload it to the suggested object-storage location.
3. Find every reference to the old path with ripgrep, e.g.:
   ```
   rg "wealth-practice-intro\\.mp4"
   ```
4. Replace those references with the new public URL.
5. Delete the local file from the working tree once the references are updated.

## How to confirm it never happens again

The companion change to this cleanup added fences to `.gitignore` covering all the categories above. New files matching those patterns will be silently ignored by git so the same bloat cannot be re-introduced. If a new file genuinely needs to be tracked despite matching one of those patterns, use `git add --force <path>` — that requires a deliberate decision.
