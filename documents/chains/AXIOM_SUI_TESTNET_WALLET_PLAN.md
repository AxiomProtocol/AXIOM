This document defines the testnet wallet requirements for Sui Phase 6

All wallets described here are testnet-only.

## 2. Wallet Requirements

### 2.1 Deployer / Admin Wallet (Testnet)

One wallet is required for Phase 6 testnet operations:

| Property | Requirement |
|---|---|
| Network | Sui Testnet (or Devnet) |
| Key type | ed25519 (recommended) or secp256k1 |
| Purpose | Package publication, AdminCap holder, campaign funding |
| Custody | Internal operator — NOT BitGo (BitGo does not support Sui) |
| Format | Single keypair generated by Sui CLI |
| Storage | Replit Secret (`SUI_TESTNET_ADMIN_PRIVATE_KEY`) — never committed to repo |

### 2.2 Test Claimant Wallets (Testnet)

For testing the claim flow, 2–3 additional testnet wallets are needed:

| Purpose | Count | Source |
|---|---|---|
| Valid claimant (in merkle tree) | 2 | Sui CLI or browser wallet |
| Invalid claimant (not in tree) | 1 | Sui CLI or browser wallet |

These do not require private key storage — they can be ephemeral test wallets
generated for each test run. Test claimant addresses must be recorded for
merkle tree construction.

## 3. Wallet Generation Method

### Recommended: Sui CLI

```bash
# Install Sui CLI (Rust-based, requires cargo)
cargo install --locked --git https://github.com/MystenLabs/sui.git \
  --branch testnet sui

# Generate a new keypair
sui keytool generate ed25519

# Output: address, publicKey, keyScheme
# Private key is stored in Sui CLI keystore (~/.sui/sui_config/sui.keystore)
```

**IMPORTANT:** Extract the private key from the keystore and store it
in Replit Secrets as `SUI_TESTNET_ADMIN_PRIVATE_KEY`. Never commit the
keystore file to the repository. Add `~/.sui/` to `.gitignore` if using
Sui CLI locally.

### Alternative: Sui Browser Wallet (Mysten Labs)

The official Sui Wallet browser extension can generate a keypair and
export the private key. Suitable for quick testnet testing.

## 6. Address Management

### Address Format
Sui addresses are 32-byte hex strings prefixed with `0x`:
```
0x<64 hex characters>
```
Example: `0x1a2b3c...` (64 hex chars)

### Address Recording
When the Phase 6 deployer wallet is provisioned:
1. Record the testnet address in this document (Section 7)
2. Store the private key in Replit Secrets as `SUI_TESTNET_ADMIN_PRIVATE_KEY`
3. Do NOT store the private key in this document or any code file
4. Fund the address via the testnet faucet
5. Confirm balance via Suiscan Testnet: https://testnet.suiscan.xyz/

## 8. Security Expectations (Testnet)

Testnet wallets hold no real value. However, the following practices
apply regardless:

- Private keys stored only in Replit Secrets — never in code, docs, or logs
- Testnet admin wallet private key not shared outside the operations team
- Wallet access revoked or rotated if any key exposure occurs
- The testnet wallet private key format must not appear in any `console.log`
  or server log output

---

## 9. Mainnet Wallet — Explicitly Deferred

No Sui mainnet wallet will be provisioned in Phase 5 or Phase 6.

Mainnet wallet activation requires:
- Phase 7 authorization signed by ops
- Separate custody design decision (not BitGo — Sui not supported)
- Legal review of mainnet distribution operations
- Separate mainnet env var set (`SUI_MAINNET_ADMIN_PRIVATE_KEY`)

**Do NOT use a testnet private key on Sui Mainnet.**
