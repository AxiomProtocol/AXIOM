# Axiom Smart City - Sovereign Digital-Physical Economy

## Overview
The Axiom Smart City project aims to establish America's first 1,000-acre on-chain sovereign smart city economy. It functions as a community-governed DeFi protocol with a robust treasury system and economic engine. Its core purpose is to create a model for future sovereign digital-physical economies, emphasizing self-custody and a non-custodial DeFi approach. Key capabilities include a governance token (AXM), DeFi treasury tools, real estate tokenization, DePIN infrastructure, smart city services, cross-chain interoperability, and sustainability initiatives within a decentralized, community-governed framework. The project's ambition is to build wealth together, on-chain.

## System Architecture

### UI/UX Decisions
The frontend features a modular, responsive design with white backgrounds and teal, purple, and gold accents. Branding includes "AXIOM" with a golden circular token logo and the tagline "Build Wealth Together, On-Chain." All new pages must comply with the "Axiom Protocol Design Law," which mandates serif headings, monospace data, navy/forest green/muted gold palette, light mode only, no gradients/shadows/animations, and specific UI patterns like pagination and flat solid buttons. A Lexicon Guard enforces prohibited terms.

### Technical Implementations
The core Axiom Protocol Token (AXM) is an ERC20 governance and fee-routing token on Arbitrum One, with a planned migration to Universe Blockchain (L3). The multi-phase Smart Contract Architecture on Arbitrum One covers identity, treasury, staking, emissions, and asset registries, supported by 72 verified smart contracts. The platform offers a Complete DeFi Treasury Suite with self-custody vaults, savings circles, staking, and investment pools, utilizing a HYBRID CUSTODY model. The system includes an "Active Contract Verification System" that serves as the single source of truth for AXUSD and PSM contract addresses, auto-generated and verified on-chain.

### System Design Choices
The architecture employs a "Product Factory Approach" for scalability. Arbitrum One is the current blockchain network, with a planned migration to Universe Blockchain (L3). Data management uses PostgreSQL with Drizzle ORM and MongoDB for analytics. The backend includes centralized contract configuration, a dedicated contract service, and chain validation middleware. Key active features include the DEX V2 Ecosystem, an Institutional Observer Dashboard, a Lending Fund (SEC Reg D 506(c) compliant), the Axiom Capital Program, Euler V2 AXUSD Lending Markets, the MIRDT (Market Intelligence & Risk Disclosure Terminal) for probabilistic trend-following analysis, and **Axiom Sentinel** — the unified capital decision and risk authorization layer.

**Axiom Sentinel:** This component acts as the unified capital decision and risk authorization layer across all Axiom products. It converts MIRDT market intelligence signals into authorized capital actions with cryptographic audit trails. Its architecture involves an in-app Next.js service as the control plane, manual API triggers for job scheduling, Drizzle + PostgreSQL for the database, mixed onchain/offchain gating, and an append-only DB with a hash chain for auditing. Core engines include `RegimeEngine`, `ConfidenceCalibrator`, `ConfirmationEngine`, `PortfolioEngine`, `AuthorizationService`, and `AuditLogger`. Sentinel also incorporates a circuit breaker, notification hooks, and reusable capital action gating with risk constraints.

**Founder Operations Dashboard:** This internal tool provides a 4-tab dashboard for System Overview, Capital Allocation, Risk Checkpoints, and Operations Log, along with an interactive playbook. It aggregates live data from various Axiom components and includes 6 mandatory Guard Rails for operational safety. The **Playbook** page (`/founder-ops/playbook`) has 5 tabs: Overview, Contract Registry, 52-Week Phases, Guard Rails, and **Operations**. The Operations tab provides a PSM Operations Console for Week 1-2 execution: live on-chain PSM status for both Primary (GENIUS) and Euler (Original) ecosystems via `/api/founder-ops/psm-status`, mint/redeem execution through MetaMask (ethers v6 BrowserProvider), and automatic transaction logging via `/api/founder-ops/log-psm-op` (server-side on-chain tx verification, no client-side auth keys). DO NOT MIX enforcement requires explicit checkbox confirmation for Euler ecosystem operations. PSM ABI and constants are in `lib/psm/abi.ts`.

**Solvency and Reserve Transparency:** The `/solvency` page is a three-mode institutional solvency console with Allocator, Clearinghouse, and Regulatory views. It combines live metrics from a database-backed snapshot system (`solvencySnapshots` table) with institutional disclosure content. The **Allocator view** shows capital adequacy metrics, asset composition, the capital waterfall, and AME adaptive targets vs actuals. The **Clearinghouse view** provides AXUSD stability assessment (with GROSS/NET liability mode selector), deterministic stress test scenarios (5 predefined: Market Correction, Liquidity Crisis, Black Swan, Stablecoin Depeg, Governance Attack), AME stress simulator, hard brake trigger table, and historical coverage charts via recharts. The **Regulatory view** contains compliance definitions, stabilization policy modes, data integrity verification, AME methodology documentation, audit artifacts, FAQ, and full risk disclosure. APIs: `/api/solvency/metrics` (v1 contract), `/api/solvency/latest` (computed model + AXUSD stability), `/api/solvency/history` (paginated historical points), `/api/solvency/scenario` (POST stress tests, stored in `scenarioRuns` table), `/api/solvency/ingest-snapshot` (admin-protected ingestion). AME APIs: `/api/solvency/ame/latest` (GET, latest AME evaluation), `/api/solvency/ame/run` (POST, admin-protected, runs new AME evaluation from latest snapshot or manual input), `/api/solvency/ame/history` (GET, time-series metrics), `/api/solvency/ame/stress` (POST, admin-protected, runs stress scenarios against AME evaluations). The math library at `lib/solvency/` provides pure-function computations for coverage ratios, reserve ratios, policy mode determination, liquidity haircuts, and stress scenario modeling. The AME math library at `lib/ame/` provides 15 pure functions for regime scoring (RS), policy multipliers (PM), adaptive targets, hard brake triggers, stress scenario projection, and deterministic policy actions. Database tables: `solvency_snapshots`, `scenario_runs`, `disclosure_events`, `ame_input_snapshots`, `ame_evaluations`, `ame_metrics_timeseries`, `ame_stress_scenarios`.

**Adaptive Metrics Engine (AME):** The final protocol upgrade. A deterministic financial computation engine at `lib/ame/` with pure-function math (no side effects). Core capabilities: Regime Scoring (RS 0.0-1.0 from volatility/drawdown/flow/compression signals), Policy Multiplier (PM 0.5-2.0 from regime band), Adaptive Targets (CR/RR/LBR/LD adjusted by PM), 4 Hard Brake Triggers (CRISIS_LOCKDOWN at RS>0.85, FREEZE_DISTRIBUTIONS at CR<0.5, LIQUIDITY_DEFENSE at LD<0.1, REDIRECT_FLOWS at RR<0.3), Payout Factor (0.0-1.0 clamped by PM), and 5 Stress Scenarios. All AME POST endpoints require `x-admin-key` header matching `ADMIN_SOLVENCY_KEY` secret. Model version: AME-v1.0.0. All tables have CREATE TABLE IF NOT EXISTS for production auto-create safety.

**DeNet DePIN Node Integration:** This integrates decentralized storage infrastructure via DeNet Datakeeper Node. A dedicated dashboard monitors node status and storage metrics, supported by an internal Google Cloud deployment guide. The integration utilizes a client, uploader, verifier, and CID enforcement package.

**Deployment SOP:** The project exclusively uses `autoscale` for deployment. The `next.config.js` must include `output: 'standalone'`, and `package.json` scripts specify `next dev -p 5000`, `next build` with asset copying, and `start` using `node .next/standalone/server.js`. Ports are `5000` for dev and `3000` for production, with `HOSTNAME=0.0.0.0`. Health checks are available at `/api/health` and `/healthz`, with `/api/health` having zero external dependencies.
